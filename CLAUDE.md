# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

OwlPilot is a class-schedule app built for a hackathon. It has two independent npm projects with no shared root `package.json`:

- `app/`: React Native + Expo (TypeScript), run in **Expo Go** (no native builds, so only Expo Go-compatible packages).
- `server/`: small Express (CommonJS) API. It is the only thing that talks to Gemini, so the API key never ships in the app.

The UI is designed in Figma (file key `22ozX0doqUgl5Svih1DqjR`, page "Page 1"). Use the Figma MCP to read frames before building a screen. Real KSU data (sections, professors, reviews) lives in `app/src/data/` (see its README). Built so far: Splash, Welcome, About You (Step 1, Academic Profile), Select Courses (Step 2), Schedule Preferences (Step 3), and Building (animated owl) and a placeholder Results screen, plus a placeholder Home screen.

## Commands

```bash
# server (port 3000, or PORT from server/.env)
cd server && npm install && npm start

# app
cd app && npm install
npx expo start          # scan the QR code with Expo Go; add -c to clear the cache after editing app/.env
npx tsc --noEmit        # typecheck
npm run test:scheduler  # runs the scheduler for a demo student and prints the schedules (add `-- extra` for a 6-course case)
npx expo install <pkg>  # always use this instead of npm install, so versions match the Expo SDK
```

There are no automated tests (only the scheduler script above). Smoke-test the server with `curl localhost:3000/health`.

## Architecture

**Request flow:** app screen → `app/src/api.ts` (`askGemini`) → `POST {EXPO_PUBLIC_API_URL}/api/ask` → `server/index.js` → Gemini REST API (`generateContent`, key sent in the `x-goog-api-key` header). The app must never call Gemini or any third-party API directly; add new endpoints to `server/index.js` and a wrapper function in `app/src/api.ts`.

**Environment files** (all git-ignored except `.env.example`, and `.claude/settings.json` denies reading any `.env`):
- `server/.env`: `GEMINI_API_KEY`, optional `PORT`, optional `GEMINI_MODEL` (default `gemini-3.5-flash-lite`; `gemini-2.5-flash` and `2.5-flash-lite` now return 404 for new API keys, and the bigger 3.x flash models often return 503 "high demand"). The user pastes the key themselves; never ask for it.
- `app/.env`: `EXPO_PUBLIC_API_URL`. It must be the computer's Wi-Fi IP (e.g. `http://10.0.0.45:3000`), not `localhost`, because Expo Go runs on a phone. Only `EXPO_PUBLIC_*` variables reach the app bundle, so never put secrets there.

**Navigation:** React Navigation native stack, defined in `app/App.tsx`. Route names and their params live in `RootStackParamList` in `app/src/navigation.ts`. To add a screen, add it to that type, register a `Stack.Screen` in `App.tsx`, and type its props with `NativeStackScreenProps<RootStackParamList, "Name">`. `Splash` uses `navigation.replace("Welcome")` after 2 seconds so Back doesn't return to it. Flow so far: Splash → Welcome → AboutYou → SelectCourses → Preferences → Building → Results.

**Fonts and theme:** `App.tsx` loads the fonts with `useFonts` and holds the native splash (`expo-splash-screen`) until they're ready. The font keys in `app/src/theme.ts` (`fonts.title`, `fonts.body`, ...) must match the names loaded in `App.tsx`; when you need a new weight, import it in both places. Use **Outfit** for headers and titles and **Manrope** for everything else, as in the Figma design. Poppins appears in Figma only on one old title layer and a notes frame, so don't use it. Colors come from `theme.ts` (yellow `#FFC629`, black, white, light gray `#F5F5F5`), so don't hardcode hex values in screens.

**Shared profile data:** `app/src/context/ProfileContext.tsx` is a plain React Context (`ProfileProvider` wraps the navigator in `App.tsx`; read it with `useProfile()` → `{ profile, setProfile }`). `Profile` holds `major`, `year` (Freshman/Sophomore/Junior/Senior), `startYear`, `gradYear` (numbers) and `takenCourses` (course *codes* like `"CS 1301"`). `aiRules` (`AiRules`, set by Building) holds what Gemini understood from the notes. `semester` ("Spring 2027"), `campus` ("Kennesaw"/"Marietta") and `selectedCourses` (codes) are saved by SelectCourses. Fields are `null`/`[]` until the screen that owns them saves on Continue; each screen saves with `setProfile({ ...profile, ... })` so it keeps the other steps' data.

**About You screen (`AboutYouScreen.tsx`):** major is prefilled from the Welcome route param and validated against `majors` like Welcome. Year uses `Chip`s; start year (2020–2027) and graduation use `Dropdown`. Graduation options are start year to start year + 8 and the dropdown is disabled until a start year is chosen. If a new start year is after the chosen graduation year, graduation is cleared and a red "Graduation year can’t be before your start year." shows. Previously taken courses (optional) come from `src/data/courses.ts` (`courses`, `courseLabel`, `findCourse`; each `Course` has `code`, `title`, `level` 1000–4000, `prerequisites` codes and `isElective`). The list is built from the unique courses in `sections.json` (labs like CSE 1321L are left out because the scheduler pairs them automatically); prerequisites are a hand-written, approximate map in that file (the section data has none); picking one adds a `RemovableChip`, and added courses are hidden from the search list. Continue requires major, year, start year and graduation year; otherwise red errors show and it doesn't navigate.

**Select Courses screen (`SelectCoursesScreen.tsx`):** semester dropdown (next 4 terms, default Spring 2027) and campus dropdown (Kennesaw/Marietta, default Marietta) use `Dropdown` with its `label` prop. "Find your courses" is a `clearOnPick` `SearchSelect` that hides taken and already-selected courses. Selected courses are `SelectedCourseCard`s (max 8, no duplicates). "Options for You" shows up to 5 `RecommendationRow`s from `recommend(profile, selectedCodes)` in `src/logic/recommend.ts`: courses in the degree plan (`src/mock/degreePlans.ts`, `getDegreePlan(major)`: the Computer Science list uses real KSU codes (CSE 1321, CSE 1322, CSE 2300, CS 3305, CS 3410, CS 3502, CS 3503, CS 4306, CS 4308, CS 4850, MATH 1190, MATH 2202, ENGL 1101/1102, HIST 2111, POLS 1101); other majors get a small general core list. Electives are PSYC 1101 and the AI courses, marked `isElective` in `data/courses.ts`) that aren't taken or selected and whose prerequisites are all in `takenCourses`, sorted with levels that fit the year first (Freshman 1000, Sophomore 1000–2000, Junior 2000–3000, Senior 3000–4000), then by level. Continue needs at least 1 selected course (red error otherwise), saves semester/campus/selectedCourses and goes to Preferences.

**Preferences screen (`PreferencesScreen.tsx`):** `Profile.preferences` is `{ numCourses, days, times, numOnline, notes, busyTimes }` (`Preferences` type in `ProfileContext.tsx`). Number of courses is a `Dropdown` of 1 to min(6, selected courses); default is 5 or the selected count if smaller. Preferred days (Mon–Fri `Chip`s) and class times (Morning/Afternoon/Evening/Anytime) are multi-select and each needs at least 1; "Anytime" clears the others and picking any other clears "Anytime". Online classes is a `Dropdown` of 0 to numCourses and is lowered if numCourses drops below it. Notes max 300 characters with a counter. "When can’t you take classes?" is optional: `BusyTimeModal` (days, start, end in 30-min steps, 7 AM–10 PM, end must be after start) adds `RemovableChip`s, max 5, saved as `busyTimes: [{ days, start, end }]` where start/end are **minutes after midnight** (2:00 PM = 840). Days/times constants and `formatTime`/`busyTimeLabel` live in `src/data/schedule.ts`. Layout follows Figma frame `22:391`: class times are `TimeCard`s (150×83, small range text, check icon when selected), days are evenly stretched `Chip`s, the two dropdowns use `Dropdown compact` (40px, labels like "5 classes"), and the buttons use `PrimaryButton` with `fontSize` (slim) and the `outline` variant for Skip. "Generate My Schedule" validates, saves, and goes to the placeholder `Building` screen. "Skip Without Filters" saves defaults (default course count, all days, Anytime, numOnline = numCourses i.e. any, empty notes, no busy times) and goes to the same screen.

**Component notes:** `Dropdown` (modal list, `error`/`disabled` props, optional `label` for the taller Figma style with a small label above the value), `SelectedCourseCard` (yellow card with "x"), `RecommendationRow` (course + reason + yellow "+"), `RemovableChip` (gray pill with "x"). `SearchSelect` has `emptyText` and a `clearOnPick` mode (picking calls `onSelect` and empties the box; typing never picks) for multi-add lists. `Chip` takes a `style` prop and `PrimaryButton` an `arrow` prop (plus `fontSize` and an `outline` variant).

**AI preference parsing:** `POST /api/parse-preferences` in `server/index.js` takes `{ notes, days, times, busyTimes, numCourses, numOnline }` and returns `{ hardRules, softRules, summary }`. `hardRules` are times the student can't have class (`{ day: "Mon".."Fri", start: "HH:MM", end: "HH:MM" }`, within 07:00–22:00; "only free 9–10 AM" becomes the blocked time around it). `softRules` are `{ type, value, note }` with `type` one of avoidLongGaps, maxClassesPerDay, preferDay, avoidDay, preferTime, avoidTime, interest (one rule per liked subject, for picking electives later), other. `summary` is 2–5 friendly bullets. Empty notes return empty arrays without calling Gemini. Gemini is called with `responseMimeType` + `responseSchema` (don't send `thinkingConfig.thinkingBudget`, Gemini 3.x rejects it), and the reply is validated (bad days/times/types dropped). Reliability: each call times out after 12s; 503, 429, timeouts and bad JSON are retried up to 2 more times (waits of 1s then 2s), a non-retryable error like 404 skips straight to the fallback model, and when the main model fails the same loop runs on `GEMINI_FALLBACK_MODEL` (default `gemini-3.1-flash-lite`). The whole request is capped at about 25s. Successful results are cached in memory by the exact input (max 200 entries, cleared on restart), so a repeated request returns instantly; errors are never cached. On any failure the server still answers 200 with empty arrays plus `error: "AI unavailable"`, so the app never crashes. The prompt says the notes override the chips and forbids inventing rules. Hard rules are only for times the student truly can't attend ("I work", "I can't", "I'm not available", practice); dislikes ("hate", "prefer not", "would rather not") become soft rules (`avoidDay`/`avoidTime`) and add no hard rule. Only the error message is logged, never the key. The app wrapper is `parsePreferences()` in `src/api.ts` (never throws, 30s abort so the app outlasts the server's 25s limit).

**Building and Results screens:** `BuildingScreen.tsx` follows Figma frame `30:660`: `lightYellow` (`#FFEDBC`) background, the looping `assets/owl.webp` shown with `expo-image` (260px wide, aspect ratio 1152/624), "Building your schedule..." (Outfit) and a looping yellow progress bar on a white track. On open it calls `parsePreferences` with the preferences from the profile, saves the result as `profile.aiRules`, waits until at least 2 seconds have passed, then `navigation.replace("Results")`. `ResultsScreen.tsx` is a placeholder (Diana is designing the final screen): a card "Here’s what I understood" with the summary bullets, "No extra preferences" when empty, or "AI is unavailable right now. Using your selected options only." plus a "Try again" button (calls `parsePreferences` again and saves the new `aiRules`, with a spinner) when `aiRules.error` is set. Below it, `buildSchedules(profile)` results are shown as simple `ScheduleCard`s ("Schedule 1–3", then "Worth considering" if any): course, professor + rating, days/times, building/room, "Full, waitlist (N)" and "Suggested" badges, plus red notes when a course could not fit.

**Real data (`app/src/data/`):** `sections.json` (801 Spring 2027 sections, 57 courses) is about 300 KB, so **never open it in full** (`.claude/settings.json` denies reading it; look at `sections.sample.json` and `README.md` for the format, or summarize it with a small node script). The app imports it normally through `src/data/sections.ts`, which exports typed `sections`, `professors` and `findProfessor(name)` (ratings from `professors.json`; unknown professor = "No ratings yet"). `reviews.json` is not used by the app yet (send Gemini only the reviews of professors in the chosen schedule).

**Scheduler (`src/logic/scheduler.ts`, plain code, no AI):** `buildSchedules({ major, year, takenCourses, campus, selectedCourses, preferences, aiRules })` returns `{ schedules (top 3), worthConsidering, notes }`. Each `ScheduleItem` has the lecture `Section`, its `lab` (paired automatically when `<code>L` exists and does not overlap the lecture), `professor`, `rating`, `blocks`, `online`, `waitlist`, `waitCount`, `suggested`, `suggestedReason`; `meetingLines(item)` gives display text like "Mon, Wed 11:30 AM–12:25 PM · Q 311".
- *Sections used:* the chosen campus ("Marietta" → "Marietta Campus") plus online (`KSU Online`, `eCore`, or mode "Fully at a Distance"/"Predominately at a Distance"; hybrids count as in person, not online).
- *Hard rules:* no overlaps (10 min travel only between two in-person classes), `busyTimes`, `aiRules.hardRules`, online count ≤ `numOnline`.
- *Full sections:* never a normal pick. A full section is tried only for a course where no open section fits with the classes already chosen, and only if its waitlist has room (`waitCount < waitCapacity`); it gets `waitlist: true` plus `waitCount` and a -15 score. Suggested courses are never waitlisted.
- *Score (higher is better):* +8 per course, (rating − 3) × 4 (missing rating = 3.0), (3 − difficulty) × 1.5, −3 per class-day outside the preferred days, −2 per class-day outside the preferred times, −2 per day on campus, soft rules (preferDay/avoidDay ±3, preferTime/avoidTime ±2, avoidLongGaps −3 per gap over 2 h, maxClassesPerDay −5 per extra class, interest +3), −15 for a waitlist pick.
- *Filling slots:* if `numCourses` > selected courses, the open slots get `recommend()` degree-plan courses first, then electives matching `interest` rules (word match on code + title, prerequisites must be in `takenCourses`); tagged `suggested`. If `numCourses` < selected, it picks the best subset. If a selected course cannot fit, it is dropped and a note says so.
- *Speed:* max 5 best options per course (plus 3 best-professor ones; 12 on a second try if nothing fits), duplicate sections (same professor/times/room) collapsed, search stops at 30,000 complete schedules. The top 3 differ from each other in at least 2 courses when possible.
- *Worth considering:* the best schedule when the preferred days/times chips are ignored (hard rules and AI soft rules still apply), shown only if its average professor rating is at least 0.5 higher than the best schedule and it is not already in the top 3.
- *Test:* `npm run test:scheduler` (`app/scripts/test-scheduler.ts`, compiled with `scripts/tsconfig.json` into `node_modules/.cache`) runs a junior CS student at Marietta (CS 3305, CSE 2300, AI 4732, CS 3503, 4 courses, Mon–Fri, Morning + Afternoon) without notes and with "I work Tuesday evenings" (the hard rule is hard-coded in the script, Gemini is not called).

## Conventions

Keep code simple and student-level: plain `StyleSheet`, `useState`/`useEffect`, no state or UI libraries. Screens go in `app/src/screens/`.

All new screens must use `src/theme.ts` (colors, fonts, shadow) and the reusable components in `src/components/` (`PrimaryButton`, `SearchInput`, `SearchSelect`, `Chip`, `StepHeader`, `SectionTitle`) instead of hardcoding styles. Add any missing color to `theme.ts`. Wrap every form screen in `ScreenContainer` so the keyboard never covers inputs and tapping outside closes it.
